Five ways to mark one task with a warning. Each example shows the same issue: an upload is retrying while another task continues normally.

Proposed progress skill wording

A warning means this task has a recoverable issue, risk, or needs attention. The run stays active and keeps its real percentage and remaining ETA. Say what happened and what the agent is doing about it.

  • Attach the warning to the existing task; keep its name and run ID.
  • Keep it visible across ordinary updates until explicitly cleared.
  • Clear it when resolved. A warning must not disappear just because progress advances.
  • Use a short, specific message: “Upload rate-limited; retrying in 30s.”
  • Keep warnings quiet: one brief emphasis when raised, no repeating pulse or completion sound. Preserve the message in task history after resolution.
# Proposed client syntax — design only, not implemented
progress-notify 'Publish release' 62 180 \
  --warning 'Upload rate-limited; retrying in 30s' \
  --description 'Built the release; upload is retrying'

# Next update after recovery
progress-notify 'Publish release' 78 90 \
  --clear-warning \
  --description 'Upload resumed; publishing remaining files'

The examples omit the usual project, run ID and chat destination flags for readability. This showcase proposes behavior and documentation; it does not change the installed app or available CLI flags.
